# Enriched GPT2 Prompt Handoff — Done

## Status

DONE.

## Problem

The desktop pipeline previously generated GPT2 prompt files from the clean 27-field row only. That row contains `SKU`, campaign strategy fields, visual fields, and copy fields, but it does not explicitly carry all product-owned values from `sku_lookup_v1.tsv`, such as:

- `BRAND_NAME`
- `PRODUCT_NAME`
- `THAI_NAME`
- `GRADE_BAND`
- `INTERNAL_DIFFICULTY`
- `DISPLAY_DIFFICULTY`
- `PRODUCT_FORMAT`
- `PUZZLE_COUNT`
- `ANSWER_KEY_STATUS`
- `OFFER_TYPE`
- `CLAIM_POLICY_CLASS`

Because GPT2 is intentionally conservative, it may return `BLOCKED_PENDING_SKU_LOOKUP` instead of assembling the final creative prompt.

## Change

`marketing-content-os/apps/social_pipeline_desktop/pipeline_service.py` now enriches every generated GPT2 prompt with:

1. `INPUT_ROW`
2. `CANONICAL_SKU_LOOKUP`
3. `PRODUCT_TRUTH_CONSTRAINTS`
4. `OUTPUT_REQUIRED`

The SKU lookup is read from:

```text
marketing-content-os/schemas/sku_lookup_v1.tsv
```

## Operator impact

The operator should no longer need to manually paste canonical SKU values into GPT2 for normal SKU rows that exist in the lookup table.

The operator-facing files under:

```text
<SKU>/_ready_for_gpt2/
```

will inherit the enriched prompt content because they are copied from the canonical handoff prompt files generated by `pipeline_service.py`.

## Product-truth safeguards

The enriched prompt explicitly tells GPT2:

- to use `CANONICAL_SKU_LOOKUP` for product-owned fields;
- not to treat marketing copy as the only source for product-owned fields;
- to keep Standard SKU claims generic as mixed Sudoku only;
- not to claim named variants, ratios, exact composition, or per-type counts;
- to display internal `DEVIL` as the customer-facing `DISPLAY_DIFFICULTY`, such as `GRANDMASTER`;
- not to imply official affiliation, fake endorsements, fake statistics, or guaranteed outcomes.
